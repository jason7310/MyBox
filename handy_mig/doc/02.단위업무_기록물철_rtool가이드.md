# [핸디 10.x] 단위업무 및 기록물철 rtool.sh 연동 및 편철 매핑 가이드

## 1. 개요 및 배경
- **목적**: ACUBE 원천 시스템에서 추출된 단위업무(16,620건) 및 기록물철(176,437건)을 핸디 그룹웨어 표준 기록관리 배치 도구(`rtool.sh`)를 통해 안전하게 등록하고, 결재문서 편철 매핑을 완료합니다.
- **핵심 원칙**: 
  1. 단위업무/기록물철은 핸디 RMS 내부 시퀀스 및 계층 트리 검증 로직이 복잡하므로 **DB 직접 INSERT를 배제하고 `rtool.sh`를 통해 등록**합니다.
  2. `rtool.sh` 구동을 위해 데이터를 **부서코드(`PROCDEPTCODE`)별 파일로 분할 추출**하여 부서별로 순차 등록합니다.
  3. **`rtool.sh` 공식 실행 옵션** (`IMG_9474.jpeg` 실물 검증):
     - 단위업무 로드: `rtool.sh -t lb -p <파일 path>`
     - 기록물철 로드: `rtool.sh -t al -p <파일 path>`
  4. **추출 파일 기본 경로**: `~/jhoms/bin/tools/data/` (즉, `/app/hso10/jhoms/bin/tools/data/`)
  5. **오픈 당일 증가분(Delta) 지원**: D-Day 시점에 새로 생성된 단위업무/기록물철만 선별 추출하여 등록 지원 (DEL 완전 제외).
  6. `rtool.sh` 등록 완료 후, 40바이트 초과 명칭/특수문자 복구 및 결재문서 편철(`APPROVAL.FOLDERID`, `FLDRMBR2`)을 고속 수행합니다.

## 2. 서버 환경 정보
- **rtool.sh 배치 절대 경로**: `/app/hso10/jhoms/bin/tools/rtool.sh`
- **추출 파일 기본 위치**: `output/rtool/` (`/app/handy_mig/output/rtool/`)
- **단위업무 원천 테이블**: `MIG1_USER.MG_BIZUNIT` (16,620건)
- **기록물철 원천 테이블**: `MIG1_USER.MG_FOLDER` (176,437건)
- **핸디 타겟 테이블**:
  - 단위업무: `INTRAWARE.BIZUNIT`
  - 기록물철: `INTRAWARE.FOLDER` (APPLID=7010), `INTRAWARE.APPRFOLDER`
  - 전체문서함: `INTRAWARE.FOLDER` (APPLID=8010)
  - 결재 편철 멤버: `INTRAWARE.FLDRMBR2`
  - 결재 문서 메타: `INTRAWARE.APPROVAL.FOLDERID`

## 3. 표준 작업 절차 (SOP)

### [1단계] 부서별 분할 추출 (Export)
핸디 마이그레이션 모듈 디렉토리(`handy_mig`)에서 다음 명령어를 실행합니다:

```bash
cd /app/handy_mig  # 또는 실제 작업 경로

# [A] 전체(Full) 마이그레이션 모드
./build_and_run.sh export-rtool all

# [B] 오픈 당일 증가분(Delta) 마이그레이션 모드 (DEL 완전 배제, 미등록 건만 추출)
./build_and_run.sh export-rtool delta
```
- **수행 내용**:
  - 기본 출력 디렉토리: `output/rtool/` (handy_mig 프로젝트 내부 통합)
  - 단위업무 폴더: `output/rtool/bizunit/` (증가분은 `bizunit_delta/`)
    - `bizunit_{DEPT_CODE}.txt` (부서별 단위업무 텍스트 파일)
  - 기록물철 폴더: `output/rtool/folder/` (증가분은 `folder_delta/`)
    - `folder_{DEPT_CODE}.txt` (부서별 기록물철 텍스트 파일)
  - 실행 스크립트:
    - 전체 모드: `output/rtool/run_rtool_all.sh`
    - 증가분 모드: `output/rtool/run_rtool_delta.sh`

---

### [2단계] rtool.sh 부서별 순차 구동 (Registration)
생성된 쉘 스크립트를 실행하여 부서별 단위업무와 기록물철을 등록합니다:

```bash
cd /app/handy_mig/output/rtool

# 전체 등록 실행 시:
chmod +x run_rtool_all.sh
./run_rtool_all.sh

# 오픈 당일 증가분 등록 실행 시:
chmod +x run_rtool_delta.sh
./run_rtool_delta.sh
```
- **실행 흐름**:
  1. 부서별 단위업무 순회 등록: `rtool.sh -t lb -p bizunit/bizunit_${DEPT}.txt`
  2. 부서별 기록물철 순회 등록: `rtool.sh -t al -p folder/folder_${DEPT}.txt`
  3. 실행 로그는 `output/rtool/logs/`에 부서별(`rtool_bizunit_${dept}.log`, `rtool_folder_${dept}.log`)로 저장됩니다.

---

### [3단계] rtool 사후 처리 파이프라인 가동 (Post-Processing)
`rtool.sh` 작업이 완료되면 다음 명령어를 실행하여 명칭 복구 및 결재 편철을 100% 매핑합니다:

```bash
cd /app/handy_mig
./build_and_run.sh post-rtool
```
- **수행 작업 (원스톱 3단계)**:
  1. `sql/folder/01.RESTORE_SPECIAL_CHARS.sql`: 40바이트 초과 명칭 및 특수문자(`^`, `#`, `\`, `/`) 원본 복구
  2. `sql/folder/02.FLDRMBR2_TOTAL_INSERT.sql`: 부서별 전체문서함(`APPLID=8010`)에 결재문서 1:1 Direct-Path 매핑
  3. `sql/folder/03.APPROVAL_FOLDER_MERGE.sql`: 
     - 임시 인덱스 생성 후 `APPRFOLDER.FLDRID`를 `APPROVAL.FOLDERID`에 초고속 MERGE
     - 기록물철 편철 멤버(`FLDRMBR2`) 적재
     - 임시 인덱스 DROP (자원 환원)

---

### [4단계] 미편철/누락 결재문서 전수 감사 (Argus Validation)
편철이 완료된 후 미편철된 문서가 있는지 전수 감사를 실행합니다:

```bash
./build_and_run.sh check-unmapped
```
- **출력 내용**:
  - 전체 결재문서 대비 편철 완료율(%) 및 미편철 건수
  - 미편철 사유별 집계 (보존부서 누락, 원천 바인드ID 미존재 등)
  - 미편철 상위 20개 부서 명단
