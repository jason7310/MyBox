긴 영문 명령어를 직접 타이핑하다가 오타가 나는 사고를 100% 방지할 수 있습니다.

```bash

./build_and_run.sh
```

## 🗺️ 전체 마이그레이션 7단계 표준 작업 흐름도

```
[0단계: 환경 준비]
  - db.properties 점검 -> 컴파일 (./build_and_run.sh compile)
       ↓
[1단계: 조직도 마이그레이션]
  - 사전 진단 (메뉴 1) -> CSV 추출 (메뉴 2 또는 3) -> 관리자 화면 E/F 등록
  - (또는 DB 직접 적재: 메뉴 4 ALL-ADD 모드)
       ↓
[2단계: 단위업무 및 기록물철 적재]
  - rtool 분할 추출 (메뉴 5) -> output/rtool/run_rtool_all.sh 백그라운드 실행
       ↓
[3단계: 결재문서 이관 리허설 (선택)]
  - _TEST 6종 고속 적재 및 검증 (메뉴 7) -> 검증 후 드롭 (test-drop)
       ↓
[4단계: 결재문서 본 이관 (운영)]
  - 결재문서 0~6단계 초고속 적재 (메뉴 8)
       ↓
[5단계: 사후 편철 매핑 & 파일 물리 점검]
  - rtool 사후 편철 매핑 (메뉴 6: post-rtool)
  - 본문/첨부 물리파일 전수 검증 (메뉴 9: check-file) -> 누락 파일 AS-IS 복구
       ↓
[6단계: 최종 감사 및 오픈 전 정리]
  - 이관결과 종합보고서 생성 (메뉴 10: report) -> AS-IS vs TO-BE 1:1 Diff=0 인증
  - 오픈 30분 전 폐지부서/퇴직자 숨김 (org-post-delete)
```

## 📖 단계별 상세 작업 절차 (SOP)

### [0단계] 사전 환경 준비 및 컴파일 검증
* **목적**: DB 접속 정보 및 라이브러리 상태를 점검하고 Java 소스를 최신 상태로 빌드합니다.
* **실행 명령**:
  ```bash
  # 1. 설정 파일 확인 (DB URL, 계정, storage.base.path 확인)
  vi config/db.properties

  # 2. 필수 JDBC 드라이버 확인 (lib/tibero7-jdbc.jar)
  ls -l lib/tibero7-jdbc.jar

  # 3. 소스 코드 전체 빌드 (성공 메시지 확인)
  ./build_and_run.sh compile
  ```

---

### [1단계] 조직도 마이그레이션 (Organization)

#### [A. 오픈 당일 증가분(Delta) 처리 시]
1. **사전 진단 (메뉴 1)**:
   ```bash
   ./build_and_run.sh org-delta-check
   ```
   * 부서, 사용자, 직위, 직급, 그룹/멤버, 핵심 권한(부서장 S1, 접수 D1 등)의 신규/변경 건수를 사전 확인합니다.
2. **증가분 CSV 7종 추출 (메뉴 2)**:
   ```bash
   ./build_and_run.sh export-org delta
   ```
   * `output/csv/` 경로에 7개 파일(`pos`, `rank`, `dept`, `user`, `group`, `group_member`, `auth`)이 UTF-8로 자동 생성됩니다.
3. **핸디 관리자 화면 일괄등록(E/F)**:
   * ⚠️ **외래키 참조 순서 엄수**:
     1) `pos_delta.csv`, `rank_delta.csv` (직위/직급 먼저)
     2) `dept_delta.csv` (부서)
     3) `user_delta.csv` (사용자)
     4) `group_delta.csv`, `group_member_delta.csv` (그룹)
     5) `auth_delta.csv` (권한: 부서장/접수담당자 즉시 활성화)

#### [B. 사전 모의 이관(전체) 처리 시]
* **방안 1 (CSV 업로드)**: `./build_and_run.sh export-org all` (메뉴 3)
* **방안 2 (DB 직접 고속 적재 - 프로젝트 권장)**: `./build_and_run.sh org-insert-all` (메뉴 4)
  * 전체 부서/사용자를 `STATUS='1'`(정상)으로 선등록하여 결재문서 이관 중 더미(`000000000`) 발생을 원천 차단합니다.

### [2단계] 단위업무 및 기록물철 적재 (rtool.sh)
* **목적**: 핸디 표준 도구 `rtool.sh`를 통해 수천~수만 건의 단위업무와 기록물철을 안전하게 등록합니다.
1. **rtool 전용 데이터 분할 추출 (메뉴 5)**:
   ```bash
   # 전체 이관 시
   ./build_and_run.sh export-rtool all

   # 오픈 당일 증가분만 처리 시
   ./build_and_run.sh export-rtool delta
   ```
   * `output/rtool/` 아래에 부서별 단위업무/기록물철 파일 및 실행 스크립트(`run_rtool_all.sh` 또는 `run_rtool_delta.sh`)가 자동 생성됩니다.
2. **rtool 실행 (백그라운드 nohup)**:
   ```bash
   cd output/rtool
   nohup ./run_rtool_all.sh > rtool.log 2>&1 &
   tail -f rtool.log
   ```
   * ⚠️ **주의**: 단위업무(-t lb)가 먼저 완전히 끝난 후 기록물철(-t al)이 실행되도록 스크립트 내부에 자동 제어되어 있습니다.

---

### [3단계] 결재문서 테스트 검증 (_TEST 모드) - 선택 사항
* **목적**: 운영 테이블에 영향을 주지 않고 복제 테스트 테이블(`_TEST`)에 6단계를 시험 적재하여 속도와 무결성을 사전 검증합니다.
* **실행 명령 (메뉴 7)**:
  ```bash
  ./build_and_run.sh test-all
  ```
  * 테이블 생성 $\rightarrow$ 6단계 고속 적재 $\rightarrow$ 8단계 병렬 16 인덱스 일괄구축 $\rightarrow$ 정합성 리포트까지 원클릭으로 완료됩니다.
* **테스트 데이터 확인 및 자원 회수**:
  ```bash
  ./build_and_run.sh test-verify   # 건수 및 무결성 리포트 출력
  ./build_and_run.sh test-drop     # 테스트 완료 후 테이블 완전 삭제
  ```

### [4단계] 결재문서 본 이관 (Production Migration)
* **목적**: 운영 테이블(`INTRAWARE.APPROVAL` 등 6종)에 수백만 건의 결재문서 및 첨부파일을 초고속으로 본 적재합니다.
* **실행 명령 (메뉴 8)**:
  ```bash
  ./build_and_run.sh all
  ```
* **수행되는 6단계 내부 프로세스**:
  1. `00.DISABLE_OPERATIONAL_INDEXES.sql` (운영 인덱스 비활성화로 10배 가속)
  2. `01.MAPPING_KEY_TABLE_CREATE.sql` (결재문서 고유키 매핑 테이블 생성)
  3. `02.APPROVAL_DIRECT_INSERT.sql` (결재문서 본체 16병렬 고속 적재)
  4. `03.SEND_DIRECT_INSERT.sql` (시행발송 정보 적재)
  5. `04.PARTICIPANT_DIRECT_INSERT.sql` (결재선 정보 적재)
  6. `05.FLOW_DIRECT_INSERT.sql` (참여흐름 정보 적재)
  7. `06.DOCUMENT_DOCMBR_DIRECT_INSERT.sql` (본문/첨부 메타데이터 적재)
  8. `08.REBUILD_OPERATIONAL_INDEXES.sql` (인덱스 병렬 일괄 재구축)

> 💡 **수신 첨부 중복 정리 도구 (선택)**:
> ```bash
> ./build_and_run.sh check-dup    # 중복 첨부파일 점검 및 절감 예상 용량 산출 (안전 모드)
> ./build_and_run.sh clean-dup    # 실제 디스크 중복 파일 삭제 및 DB 매핑 정상화
> ```

### [5단계] 사후 편철 매핑 & 물리 파일 전수 감사

#### 1. 기록물철 사후 편철 매핑 (메뉴 6)
* **실행 명령**:
  ```bash
  ./build_and_run.sh post-rtool
  ```
* **수행 작업**:
  1. 특수문자 및 명칭 원본 복구 (`01.RESTORE_SPECIAL_CHARS.sql`)
  2. 부서별 전체문서함(8010) 매핑 적재 (`02.FLDRMBR2_TOTAL_INSERT.sql`)
  3. 결재문서 편철 매핑 및 `APPROVAL.FOLDERID` 일괄 업데이트 (`03.APPROVAL_FOLDER_MERGE.sql`)
* **편철 결과 감사**:
  ```bash
  ./build_and_run.sh check-unmapped   # 미편철 문서 감사 및 편철율(99.x%) 리포트
  ```

#### 2. 전자결재 물리 파일 전수 감사 (메뉴 9)
* **실행 명령**:
  ```bash
  ./build_and_run.sh check-file --intraware --threads=16
  ```
* **동작 원리**:
  * DB 레코드 대비 실제 NAS 디스크 상의 물리 파일 누락(404) 및 0바이트를 16개 스레드로 초고속 전수 점검합니다.
  * ⭐ 열람 시 자동 생성되는 `HOX 002` 파일은 점검 대상에서 안전하게 제외되어 오탐이 없습니다.
* **누락 파일 발생 시 원터치 복구**:
  * 점검 완료 시 `output/file_check/copy_missing_from_asis_*.sh` 쉘 스크립트가 자동 생성됩니다.
  * AS-IS 원천 스토리지에서 누락된 파일만 정확히 핀포인트로 복사(rsync)해 올 수 있습니다.

## 🚨 비상 대응 및 주의사항 (SOP Rules)

1. **로컬 Mac에서 폐쇄망 IP 직접 접속 절대 금지**:
   * `192.168.204.x` 대역에 Mac에서 접속을 시도하면 패킷 드롭으로 무한 대기(Hang)가 발생합니다.
   * 모든 쉘 및 SQL 실행은 **폐쇄망 이관 서버(Rocky Linux 콘솔)**에서 직접 수행해야 합니다.
2. **오픈 당일 조직도 DEL 배제 원칙**:
   * 오픈 당일 증가분 반영 시에는 절대 `DEL` 작업을 수행하지 마십시오.
   * `pos_delta`, `rank_delta`, `dept_delta`, `user_delta` 등은 `ADD/MOD`만 반영하고, `DEL` 처리는 오픈 후 사후 처리합니다.
3. **외래키 순서 준수**:
   * 관리자 화면 E/F 등록 시 반드시 **직위/직급 $\rightarrow$ 부서 $\rightarrow$ 사용자 $\rightarrow$ 그룹 $\rightarrow$ 권한** 순서를 지켜야 합니다.
4. **⭐ 프로그램 구동 중 무한 대기(Hang) 발생 시 긴급 강제 종료 (Kill) 절차**:
   * 네트워크 지연, DB 락(Lock), 스토리지 I/O 블로킹 등으로 프로세스가 멈춘 경우 즉시 아래 중 하나를 실행합니다:
   ```bash
   # 방법 A (가장 빠름): 독립 비상 킬 스크립트 실행
   ./kill_mig.sh

   # 방법 B: build_and_run 명령어 이용
   ./build_and_run.sh kill

   # 방법 C: 대화형 메뉴에서 'k' 입력 엔터
   ./build_and_run.sh
   # -> 메뉴 선택: k
   ```
   * **동작 순서**:
     1) `com.handy.mig.*` 대상 모든 Java 프로세스 탐색 및 출력
     2) 1단계: `kill -15` (안전 종료 시도)
     3) 3초 대기 후 미종료 시 2단계: `kill -9` (확실한 강제 즉각 사살)
     4) 잔여 PID 및 임시 파일 정리 완료
   * **프로세스 상태 조회**: `./build_and_run.sh status` 또는 메뉴 `s` 로 현재 실행 중인 마이그레이션 프로세스 유무를 실시간 확인할 수 있습니다.
