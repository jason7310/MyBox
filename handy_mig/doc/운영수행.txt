 최종 개정일 : 2026-10-15
 문서 목적   : 운영 오픈 당일 또는 실 운영 이관 작업 시, 무장애·무결점 데이터 이관을 완벽하게 달성하고
               엔지니어의 오작동 및 작업 실수를 원천 차단하기 위한 엔드투엔드(End-to-End) 운영 표준 가이드

 1. 엔지니어 필수 준수 수칙 (Golden Rules & Critical Warnings)
----------------------------------------------------------------------------------------------------
 [수칙 1] 테스트 환경(_TEST) 사전 리허설 필수 완료 확인!
   - 본 운영 작업을 실행하기 전, 반드시 테스트 테이블 기반 리허설(./build_and_run.sh test-all)을
     최소 1회 이상 완수하고 정합성 리포트가 100% 정상인지 확인하십시오.
   - ⚠️ 사전 리허설 없이 운영 데이터 적재를 진행하는 것은 엄격히 금지됩니다.

 [수칙 2] 명령어 교차 검증 (절대 혼동 금지!)
   - 운영 적재 명령어 : ./build_and_run.sh all  (또는 ./build_and_run.sh run sql/00~08)
   - 테스트 명령어    : ./build_and_run.sh test-* (⚠️ 운영 작업 중에는 test- 명령어 사용 금지!)

 [수칙 3] TAC 2-node 인터커넥트 Cache Ping 병목 방지
   - 대용량 데이터 적재 시 2개 노드 간 블록 전송 경합으로 인한 성능 저하를 방지하기 위해,
     config/db.properties의 db.url 은 반드시 '1번 노드 VIP(가상 IP)'로 고정되어 있어야 합니다.

 [수칙 4] 대용량 고속 로딩 아키텍처 준수 (Fast-Bulk Architecture)
   - 운영 테이블에 인덱스가 활성화된 채로 수백만 건을 INSERT하면 수십 배의 I/O 지연이 발생합니다.
   - 반드시 [00단계 인덱스 정지(UNUSABLE)] -> [고속 Direct-Path 병렬 적재] -> [08단계 인덱스 일괄 재구축]
     순서를 엄격하게 준수하십시오. (./build_and_run.sh all 실행 시 자동 적용)

 2. 사전 환경 점검 (Pre-Flight Check)
----------------------------------------------------------------------------------------------------
 작업 디렉토리 이동:
   cd /Users/jaesunglee/dev/handy/mig/handy_mig

 [점검 1] Java 런타임 환경 (Java 17 LTS 필수)
   java -version
   -> 'openjdk version "17.0.x"' 출력 확인

 [점검 2] Tibero 7 JDBC 드라이버 배치 확인
   ls -l lib/tibero7-jdbc.jar
   -> 파일 크기 및 권한 정상 확인

 [점검 3] 운영 DB 접속 설정 및 병렬도(Parallel Degree) 확인
   cat config/db.properties
   -> 확인 항목:
      - db.url          : 1번 노드 VIP 확인 (예: jdbc:tibero:thin:@10.x.x.11:8629:tb7)
      - db.username     : INTRAWARE (운영 계정)
      - parallel.degree : 16 (서버 CPU Core에 맞춰 권장 16 설정)
      - storage.base.path: 실제 핸디 파일 스토리지 마운트 경로 (/data 등)

 [점검 4] 소스 컴파일 최신 상태 확인
   ./build_and_run.sh compile
   -> '[성공] 컴파일 완료 (bin)' 확인

 [점검 5] 테이블스페이스 및 아카이브 여유 공간 확인 (DBA 협조)
   - 데이터 테이블스페이스 (HDATA_1)  : 최소 100GB 이상 여유 확인
   - 인덱스 테이블스페이스 (HINDEX_1) : 최소 150GB 이상 여유 확인
   - Tibero 아카이브 로그(Archive Log) 디스크 공간 모니터링 (대용량 적재 시 급증 대비)

 3. 운영 사전 진단 및 기초 조사 (Pre-Migration Diagnosis)
----------------------------------------------------------------------------------------------------
 실 데이터 적재 전, 원천 데이터의 정합성과 인덱스 구조를 사전 검증합니다.

 [진단 1] 운영 DB 실제 인덱스 구성 전수 추출 및 DDL 확보
   명령어 : ./build_and_run.sh extract-indexes
   목적   : 운영 결재 테이블(6종)에 실제 적용되어 있는 인덱스명, 컬럼 목록, DDL을 전수 추출하여
            'logs/latest_01.EXTRACT_PRODUCTION_INDEXES.log'에 영구 보존합니다.

 [진단 2] 원문서(ORIGIN_DOC_ID) 링크 정합성 사전 진단
   명령어 : ./build_and_run.sh validate
   목적   : AS-IS 원문서 링크 대상 문서 중 정상 매핑 비율과 미매핑(00000000000000000000) 건수를
            사전에 통계로 확인하여 데이터 이상 유무를 사전 판정합니다. (logs/latest_validate.log 저장)

 [진단 3] 수신문서 중복 첨부파일(DOCUMENTTYPE=100) 사전 점검 (안전 모드)
   명령어 : ./build_and_run.sh check-dup
   목적   : 원기안문서 첨부를 재참조하지 않고 중복 생성된 수신 첨부 건수와 디스크 절감 예상 용량을
            화면 및 'report/duplicate_files_to_delete.txt' 파일로 사전 산출합니다. (삭제하지 않음)

 4. 본 작업 표준 실행 시나리오 (Execution SOP)
----------------------------------------------------------------------------------------------------

 [전체 이관 흐름 요약 (3단계 무결점 마이그레이션 아키텍처)]
 ┌────────────────────────────────────────────────────────────────────────────────────────┐
 │ [1단계: 조직도 선행 이관]                                                              │
 │   - ALL-ADD 방식으로 부서/사용자 전원 STATUS = '1'(정상) 선등록                         │
 │   - 방식 1 (DB 직접): ./build_and_run.sh org-insert-all                               │
 │   - 방식 2 (CSV 배치): ./build_and_run.sh export-org all 후 E/F 일괄 등록              │
 ├────────────────────────────────────────────────────────────────────────────────────────┤
 │ [2단계: 전자결재 대용량 초고속 이관]                                                   │
 │   - ./build_and_run.sh all (0단계~8단계 일괄 실행)                                     │
 │   - Fast-Bulk 인덱스 우회 + Direct-Path 적재로 과거 수백만 건 결재문서 100% 매핑 보존  │
 ├────────────────────────────────────────────────────────────────────────────────────────┤
 │ [3단계: 오픈 직전 사후 정합성 처리 및 조직도 삭제 후처리]                              │
 │   - 물리 파일 점검: ./build_and_run.sh check-file                                     │
 │   - 조직도 후처리: ./build_and_run.sh org-post-delete (폐지부서/퇴직자 STATUS='4' 전환) │
 │   - 최종 오픈 승인(Sign-Off)                                                           │
 └────────────────────────────────────────────────────────────────────────────────────────┘

 ---------------------------------------------------------------------------------------------------
 [Phase 1] 조직도 선행 적재 (ALL-ADD 방식 권장)
 ---------------------------------------------------------------------------------------------------
 * 목적 : 과거 결재문서 작성자/결재선/수발신 매핑 누락(000000000 더미)을 0건으로 차단하기 위해
          폐지부서와 퇴직자를 포함한 전체 조직도를 선행 등록합니다.

 * 실행 방법 (환경에 맞춰 택1):
   - [방법 1: DB 직접 적재 시]
       ./build_and_run.sh org-insert-all
       -> MIG1_USER에서 INTRAWARE로 전체 부서/사용자를 STATUS='1'로 Direct-Path 고속 적재
   - [방법 2: CSV 파일 연계 시]
       ./build_and_run.sh export-org all
       -> output/csv/dept_all.csv, user_all.csv 생성 후 핸디 E/F 배치 일괄 등록

 ---------------------------------------------------------------------------------------------------
 [Phase 2] 전자결재 본 작업 일괄 실행 (⭐ 오픈 당일 강력 권장)
 ---------------------------------------------------------------------------------------------------
 * 특징 : 컴파일 과정 없이 즉시 0단계부터 8단계까지 순차적 고속 실행. 오류 발생 시 자동 중단.
 * 명령어:
     ./build_and_run.sh all

 * 자동 수행 순서:
   [0단계] sql/00.DISABLE_OPERATIONAL_INDEXES.sql
          -> 운영 테이블 인덱스를 UNUSABLE 처리하여 INSERT I/O 부하 90% 제거
   [1단계] sql/01.MAPPING_KEY_TABLE_CREATE.sql
          -> 원천 키와 TO-BE 키 간 고속 1:1 매핑 테이블(MG_APPR_KEY) 생성 및 인덱스 구축
   [2단계] sql/02.APPROVAL_DIRECT_INSERT.sql
          -> 본문 결재문서(APPROVAL) DIRECT-PATH PARALLEL 16 고속 적재
   [3단계] sql/03.SEND_DIRECT_INSERT.sql
          -> 대외/대내 시행발송(SEND) 고속 적재
   [4단계] sql/04.PARTICIPANT_DIRECT_INSERT.sql
          -> 결재선(PARTICIPANT) 고속 적재 (ALL-ADD로 퇴직자 결재선도 원본 100% 보존)
   [5단계] sql/05.FLOW_DIRECT_INSERT.sql
          -> 결재 흐름(FLOW) 1:N 이력 고속 적재
   [6단계] sql/06.DOCUMENT_DOCMBR_DIRECT_INSERT.sql
          -> 파일 메타(DOCUMENT) 및 매핑(DOCMBR) 적재
          -> ⭐ 수신문서 중복 첨부 제거(원기안 재참조)로 스토리지 50% 절감 자동 적용
   [8단계] sql/08.REBUILD_OPERATIONAL_INDEXES.sql
          -> 운영 인덱스 병렬 16 NOLOGGING 고속 일괄 재구축 후 LOGGING 자동 전환

 ---------------------------------------------------------------------------------------------------
 [Phase 3] 오픈 직전 사후 정합성 처리 및 조직도 삭제 원터치 일괄 후처리 (Post-Delete)
 ---------------------------------------------------------------------------------------------------
 * 목적 : 결재문서 이관을 위해 '정상'으로 선등록해 둔 조직도 중, 폐지부서와 퇴직자만 원터치로
          STATUS = '4' 및 결재/수발신함을 비활성화하여 신규 결재선 및 조직도 노출을 완벽 차단.
 * 명령어:
     ./build_and_run.sh org-post-delete

 * 자동 수행 작업:
   1) 폐지 부서 STATUS = '4', RECV_BOX_F = '0', BOX_F = '0' 일괄 갱신
   2) 퇴직 사용자 STATUS = '4', SANC_BOX_F = '0', RECV_SEND_F = '0' 일괄 갱신
   3) 퇴직자 불필요 직무 권한(USR_AUTH) 삭제 (부서장, 접수담당 등 자동 지정 오류 원천 방지)
   4) 부서 및 사용자 상태별 통계 리포트 즉시 출력 (0.1초 소요)

 ---------------------------------------------------------------------------------------------------
 [선택적 대안] 단계별 정밀 관제 단독 실행 (특정 구간 집중 모니터링 시)
 ---------------------------------------------------------------------------------------------------
 각 단계를 엔지니어가 직접 확인하며 하나씩 진행할 때 사용합니다:

 Step 0. 인덱스 비활성화 : ./build_and_run.sh run sql/00.DISABLE_OPERATIONAL_INDEXES.sql
 Step 1. 키 매핑 테이블 : ./build_and_run.sh run sql/01.MAPPING_KEY_TABLE_CREATE.sql
 Step 2. 결재문서 적재   : ./build_and_run.sh run sql/02.APPROVAL_DIRECT_INSERT.sql
 Step 3. 시행발송 적재   : ./build_and_run.sh run sql/03.SEND_DIRECT_INSERT.sql
 Step 4. 결재선 적재     : ./build_and_run.sh run sql/04.PARTICIPANT_DIRECT_INSERT.sql
 Step 5. 결재흐름 적재   : ./build_and_run.sh run sql/05.FLOW_DIRECT_INSERT.sql
 Step 6. 첨부/매핑 적재  : ./build_and_run.sh run sql/06.DOCUMENT_DOCMBR_DIRECT_INSERT.sql
 Step 7. (선택) 물리파일 : ./build_and_run.sh clean-dup  (디스크 상의 실제 중복 파일 삭제 및 용량 회수)
 Step 8. 인덱스 일괄구축 : ./build_and_run.sh run sql/08.REBUILD_OPERATIONAL_INDEXES.sql
 Step 9. 조직도 삭제후처리: ./build_and_run.sh org-post-delete

 5. 사후 정합성 검증 및 데이터 무결성 승인 (Post-Migration Sign-Off)
----------------------------------------------------------------------------------------------------
 마이그레이션 적재 완료 후, 아래 5대 지표를 검증하여 최종 오픈 승인(Sign-Off)을 내립니다.

 [검증 1] 테이블별 적재 건수 전수 대조
   - 원천 MG_APPROVAL 총 건수 == TO-BE APPROVAL 총 건수 (100% 일치 확인)
   - PARTICIPANT 건수와 FLOW 건수의 정상 매핑 확인

 [검증 2] 결재문서(APPROVAL) 필수 컬럼 무결성 점검
   - APPRID NULL 여부         : 0건 (반드시 0건이어야 함)
   - TITLE NULL 여부          : 0건 (제목 누락 없음)
   - DRAFTERID NULL 여부      : 0건 (ALL-ADD 선행 시 미매핑 0건)
   - DRAFTERNAME NULL 여부    : 0건 (원본 성명 100% 보존)
   - DOCATTR 길이 유효성      : 80자리 표준 100% 만족

 [검증 3] 결재선(PARTICIPANT) 성명 및 이력 보존 검증
   - SIGNERNAME NULL 여부     : 0건 (퇴직자라도 당시 결재 성명 원본 보존)
   - RETIRED_OR_DEFAULT_CNT   : 퇴직자 기본값 처리 건수 확인

 [검증 4] 수신문서 첨부 중복 제거 및 스토리지 절감 검증
   - DOCMBR(논리 첨부) 총 건수 > DOCUMENT(물리 첨부) 총 건수
   - 절감된 중복 건수만큼 물리 스토리지 용량(GB) 영구 절감 달성 확인

 [검증 5] 인덱스 상태(STATUS) 전수 정상(VALID) 확인
   - sql/08.REBUILD_OPERATIONAL_INDEXES.sql 실행 로그에서 모든 인덱스의 STATUS가
     'VALID' 상태로 전환되었는지 전수 확인. ('UNUSABLE' 상태가 남아있으면 즉시 재구축)

 6. 장애 발생 시 긴급 조치 가이드 (Troubleshooting & Emergency Rollback)
----------------------------------------------------------------------------------------------------

 [상황 1] 특정 INSERT 단계에서 에러가 발생하여 작업이 중단된 경우
   - 원인 파악 : logs/latest_<SQL_NAME>.log 파일에서 오류 메시지(ORA/TBR 에러) 확인
   - 조치 절차 :
     1) 실패한 테이블의 적재 데이터를 TRUNCATE 하여 초기화:
        TRUNCATE TABLE INTRAWARE.<해당테이블명>;
     2) 원인 수정 후 해당 단계부터 단독 재실행:
        ./build_and_run.sh run sql/<해당단계>.sql
     3) 이후 다음 단계를 이어서 실행.

 [상황 2] 세션이 멈추거나 락(Lock) 경합이 발생한 경우
   - 증상 : CPU 사용량이 없으면서 배치가 더 이상 진행되지 않음
   - 조치 :
     1) Tibero 세션 조회:
        SELECT SID, SERIAL#, USERNAME, STATUS, OSUSER, MACHINE, PROGRAM 
          FROM V$SESSION WHERE USERNAME = 'INTRAWARE';
     2) 블록 경합 또는 좀비 세션 강제 종료:
        ALTER SYSTEM KILL SESSION (sid, serial#);

 [상황 3] "TBR-21013: Insufficient tablespace space" 공간 부족 발생 시
   - 조치 : DBA에게 즉시 해당 테이블스페이스 데이터파일 추가(ADD DATAFILE) 또는 자동확장(AUTOEXTEND ON) 요청.

 [상황 4] 인덱스 REBUILD 중 "TBR-07010: Index is already in VALID state"
   - 원인 : 이미 빌드 완료된 인덱스
   - 조치 : 정상 동작이므로 무시하고 진행.

 * 반출 대상 파일 (handy_mig/logs/ 에 자동 생성):
   1) 운영 인덱스 전수 DDL : logs/latest_01.EXTRACT_PRODUCTION_INDEXES.log
   2) 원문서 키 매핑 진단  : logs/latest_validate.log
   3) 중복 첨부파일 점검   : logs/latest_dup_cleaner.log
