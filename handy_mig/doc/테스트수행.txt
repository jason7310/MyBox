 1. 엔지니어 필수 준수 수칙 (Golden Rules & Warnings)
----------------------------------------------------------------------------------------------------
 [규칙 1] 명령어 혼동 절대 금지!
   - 운영 적재 명령어 : ./build_and_run.sh all  (⚠️ 오픈 당일 또는 실 운영 이관 시에만 사용)
   - 테스트 명령어    : ./build_and_run.sh test-* (사전 점검, 리허설, 쿼리 튜닝 시 항상 사용)
   - 테스트 작업 시에는 반드시 접두사 'test-'가 붙은 명령어를 사용하십시오.

 [규칙 2] TAC 2-node 인터커넥트 경합 방지
   - 대용량 데이터 적재 시 TAC 노드 간 블록 전송(Cache Ping) 병목을 방지하기 위해,
     config/db.properties의 접속 IP는 반드시 '1번 노드 VIP'로 고정되어 있는지 확인하십시오.

 [규칙 3] 반복 테스트 시 DROP 대신 TRUNCATE(test-clean) 사용
   - 테스트를 여러 번 반복할 때 매번 test-drop을 하면 인덱스를 매번 재생성해야 하므로 심각한 시간 낭비가 발생합니다.
   - 데이터만 비우고 즉시 다시 테스트할 때는 반드시 'test-clean'(0.1초 완료)을 사용하십시오.

 3. 표준 테스트 작업 시나리오 (Scenarios)
----------------------------------------------------------------------------------------------------

 [시나리오 A] 최초 1회 테스트 환경 구축 (테이블 및 인덱스 준비)
 ---------------------------------------------------------------------------------------------------
 * 목적 : 운영 테이블(APPROVAL 등 6종)과 100% 동일한 구조의 _TEST 테이블 및 고속 인덱스 생성
 * 명령어:
     ./build_and_run.sh test-create
 * 생성되는 테이블:
     - INTRAWARE.APPROVAL_TEST    (결재문서)
     - INTRAWARE.SEND_TEST        (시행발송)
     - INTRAWARE.PARTICIPANT_TEST (결재선)
     - INTRAWARE.FLOW_TEST        (참여흐름)
     - INTRAWARE.DOCUMENT_TEST    (물리파일 메타)
     - INTRAWARE.DOCMBR_TEST      (문서-파일 매핑)

 [시나리오 B] 원클릭 전체 테스트 파이프라인 일괄 실행 (추천)
 ---------------------------------------------------------------------------------------------------
 * 목적 : 테이블 생성(노인덱스) -> 01~06단계 초고속 적재 -> 08단계 병렬 16 인덱스 일괄구축 -> 07단계 정합성 전수 검증까지 원스톱 실행
 * 명령어:
     ./build_and_run.sh test-all
 * 수행 순서:
     1) sql/test/00.CREATE_TEST_TABLES.sql        (테이블 초기화: 인덱스 부하 없는 초고속 모드)
     2) sql/01.MAPPING_KEY_TABLE_CREATE.sql       (고속 조인용 키 매핑)
     3) sql/test/02.APPROVAL_TEST_INSERT.sql      (결재문서 고속 적재)
     4) sql/test/03.SEND_TEST_INSERT.sql          (시행발송 고속 적재)
     5) sql/test/04.PARTICIPANT_TEST_INSERT.sql   (결재선 고속 적재)
     6) sql/test/05.FLOW_TEST_INSERT.sql          (참여흐름 고속 적재)
     7) sql/test/06.DOCUMENT_DOCMBR_TEST_INSERT.sql (첨부 중복제거 고속 적재)
     8) sql/test/08.CREATE_TEST_INDEXES.sql       (⭐ 인덱스 병렬 16 NOLOGGING 일괄 고속 생성)
     9) sql/test/07.VERIFY_TEST_DATA.sql          (정합성 전수 리포트 출력)

 [시나리오 C] 반복 테스트 루틴 (쿼리 수정 후 재검증 시)
 ---------------------------------------------------------------------------------------------------
 * 목적 : 인덱스 구조를 유지하면서 데이터만 0.1초 만에 초기화하고 즉시 재적재
 * 수행 순서:
     Step 1. 테스트 데이터 초고속 비우기 (TRUNCATE)
             ./build_and_run.sh test-clean
     Step 2. 테스트 파이프라인 재실행
             ./build_and_run.sh test-all
     Step 3. 정합성 리포트 확인
             ./build_and_run.sh test-verify

 [시나리오 D] 특정 단계별 단독 테스트 (디버깅 및 특정 쿼리 집중 튜닝 시)
 ---------------------------------------------------------------------------------------------------
 * 개별 쿼리 단독 실행 명령어:
     - 결재문서만 테스트 : ./build_and_run.sh run sql/test/02.APPROVAL_TEST_INSERT.sql
     - 시행발송만 테스트 : ./build_and_run.sh run sql/test/03.SEND_TEST_INSERT.sql
     - 결재선만   테스트 : ./build_and_run.sh run sql/test/04.PARTICIPANT_TEST_INSERT.sql
     - 참여흐름만 테스트 : ./build_and_run.sh run sql/test/05.FLOW_TEST_INSERT.sql
     - 첨부파일만 테스트 : ./build_and_run.sh run sql/test/06.DOCUMENT_DOCMBR_TEST_INSERT.sql

 [시나리오 E] 테스트 완료 후 DB 자원 완전 환원 (클린업)
 ---------------------------------------------------------------------------------------------------
 * 목적 : 모든 테스트 작업이 종료된 후, 테스트 테이블과 인덱스를 완전 삭제하여 디스크 용량 환원
 * 명령어:
     ./build_and_run.sh test-drop
 * 주의: 실 운영 데이터 이관 전에는 test-drop을 실행하여 DB를 깨끗한 상태로 유지하십시오.

 4. 정합성 검증 리포트 판정 기준 (`./build_and_run.sh test-verify`)
----------------------------------------------------------------------------------------------------
 실행 시 터미널에 출력되는 4개 검증 블록의 판정 기준입니다:

 [지표 1] 테이블별 총 적재 건수 집계
   - APPROVAL_TEST 건수와 원천(MIG1_USER.MG_APPROVAL) 건수가 일치해야 함.
   - PARTICIPANT_TEST 건수와 FLOW_TEST 건수가 1:N 관계로 정상 적재되었는지 확인.

 [지표 2] 결재문서(APPROVAL_TEST) 필수 컬럼 NULL 점검
   - NULL_APPRID_CNT          : 반드시 0 이어야 정상!
   - NULL_TITLE_CNT           : 반드시 0 이어야 정상!
   - NULL_DRAFTERID_CNT       : 반드시 0 이어야 정상! (조직도 미존재 시 '000000000' 기본값 치환됨)
   - NULL_DRAFTERNAME_CNT     : 반드시 0 이어야 정상! (원본 기안자명 100% 보존)
   - INVALID_DOCATTR_LEN_CNT  : 반드시 0 이어야 정상! (핸디 10.x 표준 80자리 비트마스크 검증)

 [지표 3] 결재선(PARTICIPANT_TEST) 퇴직자 매핑 방어 현황
   - NORMAL_USER_MAPPED_CNT   : 재직자 매핑 건수
   - RETIRED_OR_DEFAULT_CNT   : 퇴직자/폐지부서 또는 조직도 미등록자로 기본값('000000000') 처리된 건수
   - NULL_SIGNERNAME_CNT      : 반드시 0 이어야 정상! (퇴직자라도 당시 결재자 성명은 100% 보존됨)

 [지표 4] 수신문서 첨부파일 중복 제거 및 스토리지 절감 효과
   - TOTAL_DOCMBR_ATTACH_CNT        : 사용자가 조회/열람 가능한 총 논리 첨부파일 건수
   - PHYSICAL_DOCUMENT_ATTACH_CNT   : 실제 물리 스토리지에 저장되는 파일 건수
   - SAVED_DUPLICATE_FILES_CNT      : 원기안문서 첨부를 재참조하여 절감된 물리 파일 건수
     -> SAVED_DUPLICATE_FILES_CNT > 0 이어야 정상 (수신문서 첨부 중복 생성 방지 및 50% 용량 절감 달성)

 5. 장애 발생 시 긴급 조치 가이드 (Troubleshooting)
----------------------------------------------------------------------------------------------------
 [증상 1] "ORA-00001: unique constraint violated" 에러 발생 시
   - 원인 : 기존에 적재된 데이터가 남아있는 상태에서 재적재를 시도함
   - 조치 : ./build_and_run.sh test-clean 실행 후 재시도

 [증상 2] "TBR-12004: Table or view does not exist" 에러 발생 시
   - 원인 : _TEST 테이블이 생성되지 않은 상태에서 INSERT 쿼리를 실행함
   - 조치 : ./build_and_run.sh test-create 실행 후 재시도

 [증상 3] "TBR-21013: Insufficient tablespace space" 에러 발생 시
   - 원인 : HINDEX_1 또는 HDATA_1 테이블스페이스 여유 공간 부족
   - 조치 : DBA에게 데이터파일 자동확장(AUTOEXTEND ON) 요청 또는 test-drop으로 이전 테스트 데이터 정리

 [증상 4] 배치 실행 중 특정 세션이 멈추거나 락(Lock)이 걸렸을 때
   - 원인 : 이전 비정상 종료로 세션 트랜잭션이 남아있음
   - 조치 : Tibero V$SESSION 조회 후 해당 테스트 세션 KILL
